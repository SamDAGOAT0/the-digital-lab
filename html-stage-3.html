LESSON 09 / STAGE 03 ELEMENT DETAILS

Attributes

HTML elements describe the content of a webpage. Attributes give those elements additional information and help control how they work.

What are attributes?

An attribute provides extra information about an HTML element. It is written inside the opening tag of that element.

Most attributes use a name and a value. The name tells the browser what information is being provided, while the value specifies it.

ANATOMY OF AN ATTRIBUTE 
<a href="https://example.com">
    Visit Example
</a>

href is the attribute name. "https://example.com" is its value.

Common HTML attributes

Different elements use different attributes. Here are some you'll encounter frequently.

  • href — specifies the destination of a link.
  • src — specifies the location of an image or media file.
  • alt — provides alternative text for an image.
  • id — gives an element a unique identifier within a page.
  • class — groups elements under a shared name.
  • title — provides additional advisory information.
  • style — applies inline CSS.
ATTRIBUTES IN ACTION 
<h1 id="main-title">
    My Website
</h1>

<p class="description">
    Welcome to my website.
</p>

<img
    src="photo.jpg"
    alt="A landscape"
    width="300"
>

<a href="about.html" title="Learn about me">
    About Me
</a>

Understanding id and class

Both id and class help identify elements, but they serve different purposes.

An id should uniquely identify one element on a page. A class can be shared by multiple elements.

ID VS CLASS 
<h1 id="page-title">My Website</h1>

<p class="highlight">First message</p>

<p class="highlight">Second message</p>

Boolean attributes

Some attributes do not need a separate value. Their presence alone means the feature is enabled. These are called boolean attributes.

For example, the disabled attribute prevents a form control from being used.

BOOLEAN ATTRIBUTE 
<button disabled>
    Unavailable
</button>

<input type="text" required>

<video controls></video>
Remember: Attributes belong inside an element's opening tag. They provide extra information or change how that element behaves.

LESSON 10 / STAGE 03 USER INTERACTION

Forms and Inputs

Websites don't just display information. They can also collect information from their visitors. This is where HTML forms come in.

What is an HTML form?

An HTML form is a section of a webpage that allows users to enter information and submit it.

Forms are used for contact pages, registration, feedback, searches and many other features.

The main container is the <form> element.

A BASIC FORM 
<form>

    <label for="username">
        Your Name
    </label>

    <input
        type="text"
        id="username"
        name="username"
    >

    <button type="submit">
        Submit
    </button>

</form>

Understanding form elements

  • <form> — contains the form.
  • <label> — describes an input.
  • <input> — creates an input control.
  • <textarea> — allows longer text.
  • <select> — creates a dropdown.
  • <option> — defines a dropdown choice.
  • <button> — creates a button.

Different input types

The type attribute changes the kind of input control displayed by the browser.

  • text — ordinary text.
  • email — an email address.
  • password — password input.
  • number — numerical input.
  • date — date selection.
  • checkbox — a selectable checkbox.
  • radio — one choice from a group.
INPUT TYPE EXAMPLES 
<input type="text">

<input type="email">

<input type="password">

<input type="number">

<input type="date">

<input type="checkbox">

<input type="radio">

Labels and names

Labels help users understand what information an input expects.

The label's for attribute should match the input's id. This connects the label to the input.

The input's name attribute identifies the information when a form is submitted.

CONNECTED LABEL AND INPUT 
<label for="email">
    Email Address
</label>

<input
    type="email"
    id="email"
    name="email"
    required
>

Making forms more useful

HTML provides attributes that help users complete forms correctly.

  • required — makes an input mandatory.
  • placeholder — shows a hint inside an input.
  • min and max — set limits where supported.
  • maxlength — limits the number of characters.

Browser validation can catch some common mistakes, but real applications still need server-side validation.

Remember: HTML forms create the interface for collecting information. Sending and storing that information usually requires additional programming or a server.

LESSON 11 / STAGE 03 MEANINGFUL STRUCTURE

Semantic HTML

Good HTML isn't only about making a webpage work. It's also about making its structure meaningful and understandable.

What does semantic mean?

The word semantic relates to meaning. Semantic HTML uses elements that describe the purpose of the content they contain.

For example, a navigation area should use <nav>, while the main content of a page should use <main>.

This makes the structure easier for developers, browsers and assistive technologies to understand.

Semantic vs non-semantic elements

A <div> is a generic container. It does not tell us what its content represents.

A <header>, on the other hand, tells us that the content is an introductory section for a page or another part of a page.

Both have their uses. The goal is to choose elements that describe the content accurately.

NON-SEMANTIC STRUCTURE 
<div>
    <div>My Website</div>

    <div>
        Home | About | Contact
    </div>

    <div>
        Main content goes here.
    </div>
</div>
SEMANTIC STRUCTURE 
<header>
    <h1>My Website</h1>
</header>

<nav>
    Home | About | Contact
</nav>

<main>
    Main content goes here.
</main>

Important semantic elements

  • <header> — introductory content.
  • <nav> — a navigation area.
  • <main> — the main content of the document.
  • <section> — a thematic section of content.
  • <article> — self-contained content that can stand on its own.
  • <aside> — related content separate from the main flow.
  • <footer> — footer information.

Understanding the difference

A <section> groups content around a theme, usually with a heading.

An <article> represents self-contained content such as a news story, blog post or independent article.

An <aside> contains related information, such as a sidebar or additional note.

A COMPLETE SEMANTIC LAYOUT 
<header>
    <h1>My Blog</h1>
</header>

<nav>
    <a href="#home">Home</a>
    <a href="#articles">Articles</a>
</nav>

<main>

    <section id="articles">

        <article>
            <h2>My First Article</h2>
            <p>This is my article.</p>
        </article>

    </section>

    <aside>
        Related information.
    </aside>

</main>

<footer>
    <p>Copyright information</p>
</footer>
Remember: Semantic HTML communicates the purpose of content. Don't choose elements only because of how they look.

LESSON 12 / STAGE 03 THE FINAL BUILD

Complete HTML Project

Twelve lessons. Three stages. One final challenge. It's time to combine everything you've learned and build a complete webpage.

Your final project

You're going to build a personal portfolio page. It will introduce you, display your interests, provide navigation, and include a contact form.

This project brings together the HTML concepts from all three stages.

What your webpage will contain

  • A proper HTML document structure.
  • A website title and metadata.
  • Semantic header, navigation, main and footer.
  • Headings and paragraphs.
  • Text formatting.
  • Links and navigation.
  • An image with alternative text.
  • Lists describing your interests.
  • A table showing your skills.
  • A contact form.
PROJECT STRUCTURE 
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>My Portfolio</title>
</head>

<body>

    <header>
        Website introduction
    </header>

    <nav>
        Website navigation
    </nav>

    <main>
        Main portfolio content
    </main>

    <footer>
        Contact and footer information
    </footer>

</body>

</html>

Before you begin

Remember that HTML is responsible for the structure and meaning of your content. The visual design will be handled by CSS in the next chapter.

Focus on making your HTML clear, organised and meaningful. You don't need to make it visually impressive just yet.
